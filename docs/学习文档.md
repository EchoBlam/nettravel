## 生成自签名证书
```
# 生成私钥
openssl genrsa -out server.key 2048

# 生成证书签名请求（CSR）
openssl req -new -key server.key -out server.csr 

# 自签名（自己当CA）
openssl x509 -req -days 365 -in server.csr -signkey server.key -out server.crt
```
此时浏览起访问会发出警告，不安全，但是选择信任后可以访问网站，如果没有证书，访问会出现不安全连接，不可以访问，

## 构建私有 CA（证书颁发机构） 并为 APISIX 签发证书的完整流程
第一部分：生成 CA 根密钥和证书（成为"自建CA"）
```bash
# 1. 生成CA根私钥（ca.key）
openssl genrsa -out ca.key 2048 && \

# 2. 生成CA证书签名请求（CSR）
openssl req -new -sha256 -key ca.key -out ca.csr -subj "/CN=ROOTCA" && \

# 3. 自签名生成CA根证书（ca.crt）
openssl x509 -req -days 36500 -sha256 -extensions v3_ca -signkey ca.key -in ca.csr -out ca.crt
```
第二部分：生成 APISIX 服务器证书（由自建 CA 签名）
```bash
# 1. 生成APISIX服务器私钥（server.key）
openssl genrsa -out server.key 2048 && \

# 2. 生成服务器证书签名请求（CSR）
openssl req -new -sha256 -key server.key -out server.csr -subj "/CN=test.com" && \

# 3. 使用CA根证书签发服务器证书
openssl x509 -req -days 36500 -sha256 -extensions v3_req \
  -CA ca.crt -CAkey ca.key -CAserial ca.srl -CAcreateserial \
  -in server.csr -out server.crt
```
## SSL 证书认证过程（结合上述命令）
当客户端（如浏览器、其他服务）访问 APISIX 时，SSL/TLS 握手过程会验证证书合法性，对应上述命令生成的文件：

1. 客户端请求 HTTPS 连接
   APISIX 发送 server.crt（服务器证书）给客户端。

2. 客户端验证证书链
   客户端会检查 server.crt 的签名者是谁（即"谁签发了这个证书"）：

server.crt 的"签发者"字段指向 ca.crt（自建 CA 的名称 "ROOTCA"）。
客户端需要验证 "ROOTCA" 是否可信：
公共 CA：浏览器/操作系统预装了公共 CA 的根证书（如 Let's Encrypt、VeriSign），自动信任。
私有 CA：需手动将 ca.crt 导入客户端的"受信任根证书列表"（否则提示"证书不受信任"）。
3. 验证签名合法性
   客户端用 CA 的公钥（从 ca.crt 中提取）解密 server.crt 中的数字签名，验证证书内容（如域名、公钥）是否被篡改：

如果签名验证通过，且域名匹配，客户端信任 APISIX，继续握手。
如果验证失败（如签名错误、CA 不受信任），客户端终止连接并提示安全警告。
4. 后续加密通信
   验证通过后，客户端用 server.crt 中的服务器公钥加密"预主密钥"，APISIX 用自己的私钥（server.key）解密，双方协商出对称加密密钥，用于后续数据传输加密。
